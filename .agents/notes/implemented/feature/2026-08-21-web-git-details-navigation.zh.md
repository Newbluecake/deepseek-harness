# Agent Note: Web Git 详情导航

Status: implemented

[English](2026-08-21-web-git-details-navigation.md) | 中文

## Problem

文件浏览器曾在同一个大型弹窗中打开 Git 变更列表和提交图。这种导航方式与右侧详情栏中的工作区文件树不一致，也让浏览文件列表变成了会中断当前操作的行为。

## Decision

会话右侧详情栏默认展示 Git 变更列表。统一的右侧 Dock 替代原先分离的文件和 Terminal 展开控件，并固定提供工作区文件列表、Git 变更、Git Tree 和 Terminal 四个入口。鼠标悬停或键盘聚焦时，目标图标和相邻图标通过不改变 Dock 尺寸的 transform 放大。Dock 的 Git Tree 入口先在详情栏展示当前分支的精简提交列表，点击展开控件后才打开包含全部分支的完整图弹窗。选择某个变更文件后，共享 store 记录其路径和暂存状态，只有这个选择会打开并排文件 diff 弹窗。关闭任一弹窗后，底层选中的详情列表保持不变。Git 变更列表支持按路径搜索，并在文件上方显示当前分支，与文件列表显示工作区路径的位置一致。Git Tree 在底部显示分支，并在 HEAD 提交上标记当前分支。

顶部标题跟随所选列表显示“文件目录”、“Git Diff”或“Git Tree”，并在三种列表中始终按相同顺序保留文件列表、Git Diff、Git Tree、全部收起、刷新和关闭控件；文件树专属操作在不可用时禁用，而不是消失。Dock 始终固定在屏幕右侧并显示在 Terminal 和文件浏览器弹窗上方，因此点击任一文件或 Git 入口都会关闭 Terminal 并打开目标视图。代码预览弹窗保持独立，并继续在选择工作区文件时打开。选择面板或任一弹窗时会清除冲突的选择，因此同一时间最多只有一个文件弹窗处于打开状态。

## Alternatives considered

**保留带标签页的统一 Git 弹窗。** 这种方案可以继续让所有 Git 内容共用一个框架，但浏览变更和历史仍然脱离文件浏览器的导航方式。

**在右侧详情栏中展示文件 diff。** 这种方案可以完全避免 Git 弹窗，但狭窄的详情栏无法清晰并排展示两个代码版本，而且检查文件时会丢失列表上下文。

## Consequences

Git 变更和工作区文件共用一个可预期的列表位置，两种需要宽屏的可视化仍使用弹窗空间。共享 store 负责列表选择和弹窗状态。组件测试固定了默认 Git 变更列表、切换文件列表、打开和关闭文件 diff，以及打开 Git Tree 时不替换所选列表的行为。
